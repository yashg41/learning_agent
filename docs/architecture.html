Three agents, three tool budgets

The separation is enforced, not conventional. A builder physically cannot call a quiz tool.

Tutor · 19 + 2

19 of the 27 MCP tools, plus WebSearch and WebFetch. Teaches, quizzes, tracks concepts, runs code. Requests demos and derivations but cannot write them — keeping save_demo off this list is what stops it emitting 30 KB of HTML inside a chat turn.

Demo builder · 3 tools

save_demo, update_demo, get_demo_html. Nothing else. Inherits the conversation by forking the session, writes to a new session id so the tutor's transcript is never appended to.

Derivation builder · 6 tools

The five derivation_* tools plus run_code — included because a derivation may need a plot. Cannot reach quiz or profile tools.

The allowlist is advisory; the denylist is what holds. The agent runs under permission_mode="bypassPermissions", which skips the check that consults allowed_tools. Only disallowed_tools is enforced in every mode. This was found the hard way — the tutor was seen writing a demo to /tmp and leaving python3 -m http.server 8000 running, exposing that directory on the network. Bash, Write, Edit, Read, Glob, Grep, Task and TodoWrite are all explicitly denied.

WebSearch and WebFetch are deliberately not denied: the tutor teaches libraries that move faster than the model's cutoff, and running code cannot answer "what is current" for an API it has never seen.

The three memory tiers

Written mechanically

conversation.jsonl on every event, and one conversation_exchanges row after every response via _extract_and_save_exchange. No model involvement — these cannot be forgotten.

Written by choice

Summaries, concepts and quiz results only land when the model calls a tool. This is where the profile is genuinely built — and where it can silently fall behind.

Editing is a tombstone, not a rewrite. The transcript is append-only, so an edit appends {"type":"supersede","from_index":N}, retracting turn N and everything after it — the edit point and everything it led to. read_turns rebuilds the survivors, and every reader must go through it or retracted turns leak back into the UI.

Specialities — the parts that are actually unusual

Fork for context, not a brief

A builder inherits the real conversation by forking the session. A prose summary of twenty turns produces a generic demo; the fork produces one about what was actually discussed. It writes to a new session id, which is what makes running it concurrently with a live chat turn safe.

Refinement resumes the builder

"Add a reset button" resumes the builder's own earlier session, which still holds both the conversation and the HTML it wrote — an incremental edit rather than a full regeneration.

Verification fails closed, in three states

verified: None means unchecked and is treated differently from False, which means checked and wrong. The tests assert both directions, because the failure that matters is not "missed a wrong step" but "called a correct step wrong" — that tells a learner a valid derivation is broken.

Deterministic episodic IDs

ex_{email}_{session}_{index} means a re-save upserts instead of duplicating, so backfill is safe to run repeatedly. The email is normalised before the ID is built — otherwise a casing difference produces a second row for the same exchange.

Images cost ~30 tokens

save_image_memory writes the file to disk and stores only the caption and path in the vector DB. A 1 MB screenshot becomes a sentence, and searches stay fast.

Prompts are documents, not literals

Eleven numbered .md files assembled by filename order. Substitution is a plain .replace — .format() chokes on the literal braces in the JSON examples, and string.Template eats $$, which would have silently broken every equation the formatting rules promise renders.

Code execution

Each learner gets their own virtualenv under data/users/<email>/venv, built on first use and marked ready only once packages install — a pip failure used to leave a permanently "ready" but empty venv.

Curriculum

215 concepts in a prerequisite DAG, loaded from backend/curriculum/*.yaml — one file per track. Cross-track edges are allowed by design — numpy_basics depends on lists — so suggest_next_topics can only offer what the learner is actually ready for.

Mastery is a three-rung ladder — introduced → practiced → mastered. A correct quiz answer promotes exactly one rung. The tutor asserts mastery via update_concept; only quizzes move it on evidence.

Known rough edges

Tier 3 grows without bound in the prompt. format_for_system_prompt emits every concept and its full free-text notes, with no cap. Measured live: 23,410 characters for 72 concepts, averaging 244 chars each — larger than all the static teaching instructions combined, and linear in concepts learned. The same reasoning was applied to demo titles ("injecting every title would cost hundreds of tokens") but never to the knowledge graph.

The Memory explorer's scatter plot discards ~70% of the signal. PCA to 2D captures 18.5% (PC1) + 12.0% (PC2) = 30.5% of variance on the live store. Two dots that look close may be far apart in the dimensions the projection dropped, and each axis is independently rescaled to [-1,1] so the plot always fills the box regardless of real spread. It also fetches with no limit, so the Exchanges view silently shows only the first 100 of 343.

knowledge.json writes are not atomic. Read-whole, mutate, write-whole with a plain json.dump — no temp-file-plus-rename, unlike memory.py and notes.py which both do it properly. Under uvicorn --reload, a crash mid-write can truncate the entire knowledge graph. It is the one store with no backup and no recovery path.

Split-brain state. The UI renders from data/users/…/sessions/ while --resume reads the CLI's own transcript under ~/.claude. Deleting one leaves the chat looking intact while the model has lost the conversation. transcripts.py mirrors the CLI copy into the project to compensate.
