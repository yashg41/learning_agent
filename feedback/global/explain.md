# Guidance when explaining concepts

- Lead with the *why* — what problem does this concept solve — before showing syntax.
- Use a concrete analogy (physical object, real-world scenario) before an abstract definition.
- Keep code examples under 10 lines unless the concept genuinely needs more.
- Always connect the new concept back to one concept the learner has already practiced or mastered.
- Show one "gotcha" example for concepts where beginners commonly trip up (mutable defaults, list aliasing, integer division, etc.).
- When a concept has a newer/older form (f-strings vs `.format()`, `match` vs `if/elif`), teach the modern one first.
